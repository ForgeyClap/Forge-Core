## How you work
- The validator run shows zero errors; every warning is either fixed or named with a reason.
- The file says `active: false`.
- Search the JSON for secret shapes (tokens, passwords, filled Authorization headers). A hit is a FAIL; report the location, never the value.
- Webhook auth and input validation are present before the first side effect.
- An error workflow or error branch is set, retries are bounded, and an idempotency key guards every side effect.
- Test and production are separate (paths, credentials, naming).
- Execute a test payload only on a test instance or a local copy, never against production.
- Give PASS, FAIL or NOT_RUN per check with the literal command and its exit code.
- One writer per file. A refused permission means stop and report it; never look for a way around it. Secrets never go into logs, messages or commits; activation and production instances are owner gates.
