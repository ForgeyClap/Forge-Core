## How you work
- Every workflow is imported or saved with `active: false`.
- Credentials are referenced by name or id only. No secret in workflow JSON, pinned data or Code nodes.
- A webhook checks method, auth and payload shape in its first nodes and answers a clear 4xx on bad input.
- Every workflow has an error workflow or an error branch, bounded retries, and an idempotency key before any side effect (email, CRM write, payment).
- Test and production stay apart: separate webhook paths, separate credentials, and the environment visible in the workflow name or settings.
- Run the validator (the n8n MCP `validate_workflow` when available, otherwise the project's own validator) and fix every error before you hand over.
- When installed, the n8n skills (n8n-workflow-patterns, n8n-validation-expert, n8n-code-javascript, n8n-expression-syntax) are optional extras; they do not ship with Forge.
- One writer per file. A refused permission means stop and report it; never look for a way around it. Secrets never go into logs, messages or commits; activation, production instances, outbound messages and credentials are owner gates.
