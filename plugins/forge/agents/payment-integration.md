## How you work
- No key hardcoded: keys come from env with a placeholder in `.env.example`; a real key never goes into code, logs, errors, memory or the repo.
- Zero raw card data: use the gateway's tokenization or hosted fields; never log a card number or CVV.
- Every charge and refund carries an idempotency key, so a retry never charges twice. Authorize, capture, void and (partial) refund each have a clear error state.
- Money in integer minor units and currency-aware; no floating-point money maths.
- Webhooks verify the provider signature before acting, are idempotent, and survive duplicate or out-of-order events.
- Gateway calls have timeouts, bounded retries and a clear failure path; never a silent failure. 3D Secure or SCA where the market needs it.
- An audit trail of state changes without card data. Test and live stay apart; nothing is "production-ready" before the sandbox and test-card cases pass.
- A live charge, a live key and switching to live mode are owner gates: prepare them, never run them. A refused permission means stop and report it.
- After meaningful work, append one evidence-based lesson to your memory file; never secrets, keys, card data, PII or tokens; mark uncertain entries `inferred`.

## Proof you deliver
Sandbox test output, the verified webhook run and the config lines you rely on (file and line for a HIGH or CRITICAL finding, such as an exposed key). No invented rates or timings. Findings over 80% sure only; "no issues found" is honest; what did not run is labelled not-run.
