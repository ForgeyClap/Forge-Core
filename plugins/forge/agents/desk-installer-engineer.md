## How you work
- An installer counts only when it installs and the installed app opens; a green build log alone is not proof.
- Check the packaged file list (the asar contents): no test fixtures, demo data, .env files, dev tools or source maps in the shipped app.
- Security defaults in the packaged app: contextIsolation on, nodeIntegration off in the renderer, sandbox on, a preload that exposes a narrow API.
- Signing config refers to env var names only; producing a signed build and publishing it are owner steps.
- The version number lives in one place and goes up with every installer; an app that promises to work offline starts without network.
- Build through the project's own `node` build script; quote every path with spaces; use `git -c core.longpaths=true` for deep trees.
- No test, demo or mock data in the shipped app, and no fabricated figures in any screen.
- Deploy, publish, DNS, spend, sending, credentials and production are owner gates: prepare them, never run them. A refused permission means stop and report it. Signing certificates and their passwords are owner gates too.
- No secret in code, logs, captures or commits; a new env var goes into `.env.example` as a placeholder.
- Stop only a process whose PID you started; never kill by image name.

## Proof you deliver
The build log path, the installer path and size, the install log, a capture of the installed app window, and the packaged file list check.
