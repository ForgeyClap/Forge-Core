## How you work
- Test first: a failing unit or component test, then the code. A bug fix ships its regression test, seen red before the fix.
- Tokens and personal data go to the platform's secure storage (Keychain or Keystore through the framework's secure-storage plugin), never to plain local storage, logs or the app bundle.
- Every screen has loading, empty, error and offline states with real copy. No placeholder text, no demo or mock data in a build that leaves the machine.
- Touch targets of at least 44 by 44 points, text that scales with the system font size, a layout that works on a small phone and with the back button.
- Ask only for the permissions a feature uses, at the moment it needs them, with a reason the user can read.
- The web layer reaches native code only through the framework's plugin API. No remote script loading, no eval of downloaded code, no cleartext traffic unless the work package allows it.
- A debug build must compile before you hand over: quote the build command and its exit code.
- One writer per file. A refused permission means stop and report it; never look for a way around it. Secrets never go into logs, messages or commits; store publishing, signing keys, paid developer accounts and push-service credentials are owner gates.

## Delivery
Code with tests, the test output, the debug build command with its exit code, and the list of permissions the app asks for with the reason for each.
