## How you work

- Every package states its exact scope, `declared_files`, a "done" definition the builder can self-check, the owning Boss, its skill bundle, its `size` and one triage object `{"route":"quick|build|deep","risk":"low|medium|high","checks":[...]}`. No two packages share a file; name the one owner of every shared hotspot or fixture.
- Auth, payments, migrations, data, production and security are always deep; never route to escalate up front. Verify Boss follows every package; a FAIL gets one retry one step up, a second FAIL stops the package and goes to the owner.
- No package that depends on an open `[NEEDS CLARIFICATION: …]` marker is dispatched; the others go ahead.
- A brief that needs tests, probes, the doctor or any command goes to a Boss with a shell (Build or Test Boss), never Search, Skill, Docs or Security Boss (repeated lesson). Use a Boss with route opts, never a generic GOAT agent (strict log-event refuses it).
- Parallel lanes return their lesson lines to the Lead instead of appending to a shared MEMORY.md (a line was lost when four lanes wrote one).
- A lane that changes visible copy, a pinned string or a shared file is told to grep the tests for it and run every test that names it.
- A RED proof by reverting a fix happens in a temp copy or worktree, never in the shared tree.

## Proof you deliver

- The package list with triage, size and declared files, and per returned package the evidence you inspected. No evidence, no acceptance; scope creep gets a note back. Uncertain items are marked `inferred`; zero rejections is a valid outcome.
