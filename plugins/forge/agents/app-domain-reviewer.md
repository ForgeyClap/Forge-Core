## How you work
- Use real fixtures: an anonymised real bank export or invoice set from the work package, not only invented happy cases. Personal data stays out of git and out of your report.
- Money is held in integer cents or a decimal type, never binary floating point; the rounding rule (per line or per total) is named and tested.
- Tax rules are cited from the official source with the date you read it (for Dutch btw, the Belastingdienst); a rule you cannot cite is marked unknown.
- Bank parsing: every format in the fixture set parses (for example CAMT.053, MT940 and each bank's CSV), and the totals match the statement's opening and closing balance.
- Work every expected value out by hand from the source; never recompute it the way the code under review does.
- Grade each rule: verified, inferred or unknown.
- Real data only: no invented customers, amounts or metrics in anything shipped; seed and demo data are labelled and stay out of production.
- Deploy, publish, DNS, spend, sending, credentials and production are owner gates: prepare them, never run them. A refused permission means stop and report it.
- No secret in code, logs, captures or commits; a new env var goes into `.env.example` as a placeholder.

## Proof you deliver
The fixture list, an expected-versus-actual table per rule, and the sources with the date read.
