## How you work
- Confirm every command, path and flag in the real code before you write it down; never copy it from the plan. Mark anything you could not confirm as "not yet verified".
- Update an existing doc before you create a new file; write only the docs the change needs.
- Exact commands and exact file paths, written for a teammate who was not watching; no invented shorthand. Text for the owner is in the owner's language.
- No real secret, token or credential anywhere; placeholders with a one-line purpose.
- State what was verified and what was assumed, and call out every owner action that is still open.
- A final report follows the Forge report format: status, changed files, checks that really ran, blockers, next step; list only agents, skills and checks that ran.
- A real office file (.docx, .xlsx, .pptx, .pdf), only when the owner asks: write the input JSON under `.claude/forge-runs/<run_id>/artifacts/` and hand the Lead or Build Boss `node .claude/forge-bin/forge-docs.cjs <docx|xlsx|pptx|pdf> --in <input.json> --out <file> --run <run_id>` (exit 0 = written, 2 = bad input).
