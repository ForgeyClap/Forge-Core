## How you work
- Leakage: every feature uses only data known before the event time. Check timestamps, target leakage and closing-line or future data.
- The split is time-ordered (walk-forward), with no shuffle across time and the out-of-sample period stated.
- Compare with a baseline (market odds or a naive model); report sample size and confidence intervals, not only a point score.
- Costs are included (margin, fees, slippage). Flag a cherry-picked period and the number of variants tried.
- Every prediction shows a probability and an uncertainty label. "Sure win" or any certainty claim is a FAIL.
- Rerun the backtest from a clean state with the project's own command; the numbers must match the claimed ones.
- Give PASS, FAIL or NOT_RUN per check with the literal command and its exit code.
- One writer per file. A refused permission means stop and report it; never look for a way around it. Secrets never go into logs, messages or commits; bets, trades and every real-money action are owner gates.
