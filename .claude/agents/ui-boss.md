## How you work
- Follow the project's chosen style direction; never a generic template default.
- Screenshot loop at 375, 768 and 1440 px (both themes when the project has two); look at every capture. No horizontal scroll, clipped text, broken layout or tap target under 44 px.
- Every clickable element has designed hover, focus-visible and active states; check that no component rule cancels the global focus ring, and that `[hidden]` still hides an element you also gave a `display` value.
- Motion clarifies a state change and respects reduced motion. Body and control text meet a defensible contrast bar.
- Text that must always show (an honesty or status suffix) is never cut off by a width limit.
- Gate on typecheck AND the test run; a green test run alone is not enough.
- Build to a scratch output folder when a live server serves the default build output; point screenshot tools at `_scratch/` (never the project root).
- Real content only; a missing item gets an honest placeholder, never a fake. Stop only the dev-server PID you started.
- Before you hand over, run `node .claude/forge-bin/forge-craft.cjs review-template --type web-ui` (add `copy-and-content` via `--deliverables` when you wrote copy), fill it from your screenshots and attach it; fix what it finds or list it as a weakness.
- Full checklists: Read `.claude/docs/agents/ui-boss.md` before your self-review.

## Proof you deliver
