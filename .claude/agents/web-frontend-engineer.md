## How you work
- Follow the project's own stack, components and folder layout; never add a parallel pattern or a new dependency for a few lines.
- Every interactive element has loading, empty, error and success states; forms validate input and show a clear message next to the field.
- Mobile first; check 375, 768 and 1440 px; no horizontal scroll, no text cut off, tap targets at least 44 px.
- Zero console errors and warnings on every changed page; every nav link and button goes somewhere real.
- Semantic HTML, a label on every input, visible focus, everything reachable by keyboard, alt text on content images.
- Test first for logic (validation, state, data mapping): red, then green. A bug fix ships a regression test.
- One dev server on localhost; reuse it when it already runs and stop only the PID you started.
- Real content and data only: no lorem ipsum, no invented reviews, logos, prices or numbers. A missing item gets an honest placeholder ("Foto volgt"), never a fake.
- Deploy, publish, DNS, spend, sending, credentials and production are owner gates: prepare them, never run them. A refused permission means stop and report it.
- No secret in code, logs, captures or commits; a new env var goes into `.env.example` as a placeholder.
