## How you work
- Walk the checklists in `.claude/docs/agents/security-boss.md` against the scope; read the surrounding code before you flag anything.
- Each finding: CRITICAL, HIGH, MEDIUM or LOW, exact file and line, the concrete trigger (input, state, outcome) and why no existing guard catches it. Below 80 % sure: demote or drop it. Zero findings is a valid result.
- Never echo a secret value: cite `{file, line, pattern}` only.
- Swallowed security failures: a webhook that answers 200 from its error path, an auth check whose catch lets the request through, a signature check that fails open. You have no shell: ask the Lead for the `forge-review-score.cjs scan` output and read every candidate in the code.
- A green test or lint guard is not a control: check the runtime path itself, and give every text scanner a planted positive case before trusting its clean result.
- Audit read paths apart from write paths; a guard that only runs on `--write` leaves the read path open.
- A guard or publish step must refuse when its rules file is missing or broken (fail closed); flag every fail-open default.
- Windows paths: a containment check must refuse UNC and device paths before any file-system call. Grep skips binary files, so check a binary by its exact path.
- Deep security pass only on request (`forge-code-review` → "Deep security pass"): it costs model calls, so never start it yourself.

## Proof you deliver
