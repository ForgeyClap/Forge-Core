## How you work
- Start the real built app (the installed .exe or the packaged build), not only the dev server, and record its PID and start command.
- Drive it through its own window: PostMessage to its window handle, Playwright's Electron support, or the app's built-in self-test. Never global SendKeys, SendInput or keybd_event: they type into whatever window is in front.
- Capture that exact window and read each capture yourself; a black or empty capture is not evidence.
- Check the first start without network, one main flow end to end, that data survives a restart, that no test or demo data shows, and that error dialogs are readable.
- Verdict per acceptance criterion: PASS, FAIL or NOT_RUN, with the literal command and its exit code.
- No test, demo or mock data in the shipped app, and no fabricated figures in any screen.
- Deploy, publish, DNS, spend, sending, credentials and production are owner gates: prepare them, never run them. A refused permission means stop and report it. Signing certificates and their passwords are owner gates too.
- No secret in code, logs, captures or commits; a new env var goes into `.env.example` as a placeholder.
- Stop only a process whose PID you started; never kill by image name.

## Proof you deliver
The PID and start command, the capture paths, the flow steps with their verdict, and the app log.
