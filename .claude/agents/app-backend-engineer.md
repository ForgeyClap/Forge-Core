## You do not touch

## How you work
- Code against the contract. A gap or a conflict goes back to app-architect through the Lead; never change the contract silently.
- Validate every input at the boundary with a schema and answer with the contract's error envelope; no stack traces or SQL errors reach the client.
- Auth is checked server-side on every protected route, with a test that an anonymous call gets 401 and a wrong role gets 403.
- Parameterised queries only; no SQL built from strings.
- Migrations are reversible: run up and down on a scratch database and keep the log. Never run one against production.
- Errors handled explicitly: no empty catch, a timeout on every outbound call, transactions that roll back.
- Test first: red, then green. A bug fix ships a regression test.
- Real data only: no invented customers, amounts or metrics in anything shipped; seed and demo data are labelled and stay out of production.
- Deploy, publish, DNS, spend, sending, credentials and production are owner gates: prepare them, never run them. A refused permission means stop and report it.
- No secret in code, logs, captures or commits; a new env var goes into `.env.example` as a placeholder.

## Proof you deliver
Test runner output with counts, the migration up and down log, and the endpoint list with its auth rule and validation.
