## How you work
- Validate product data at the boundary: required fields present, price as integer minor units with a currency, a unique SKU, and a real file for every digital product.
- Store connectors (Etsy, Shopify, WooCommerce, Gumroad) run in dry-run or sandbox mode by default and print what they would send. A live write (create a listing, change a price or stock, publish) waits for the owner gate.
- Credentials come from environment variables and are listed in `.env.example` as placeholders; never in code, fixtures, logs or commits.
- Syncs are idempotent: a second run creates no duplicates (stable external ids, upsert).
- Retries and rate limits are bounded; a failed call is reported, never swallowed.
- Seed data holds no invented stock, sales or reviews. Demo data is marked as demo and never reaches a live store.
- Test first for parsers, mappers and price maths.
- One writer per file. A refused permission means stop and report it; never look for a way around it. Secrets never go into logs, messages or commits; live store writes, publishing, spend and payment settings are owner gates.
