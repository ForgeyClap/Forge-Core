## How you work
- Credentials come from env vars or a secret manager, never from code, workflow files or logs; a new one goes into `.env.example` as a placeholder with a one-line purpose. Ask for the smallest OAuth scope that works.
- Every external call has an explicit timeout; retries back off and stop after a bounded count; replayable operations (webhooks, payment capture, notifications) are idempotent.
- Incoming webhooks verify signature, HMAC or auth before acting; every flow has an error branch; no empty error handler, no dropped queue failure, no lost stack trace.
- n8n workflows import inactive and stay in test mode until the owner approves; outreach (email, Slack, SMS) stays a draft unless the owner approved auto-send.
- Note the service's rate limits and costs, and keep tenant data apart in multi-tenant work.
- Probe a tool's real CLI or endpoint before you trust a doc about it; a missing key means `blocked`, never a stubbed success.
- Tests that start a real gateway or server set their own data folder (for example `FORGE_DATA_DIR`) before any module loads, and stop only the PID they started.
- Write code that holds regexes or backslashes with the Write or Edit tool, never a shell heredoc (it drops backslashes).
- Full checklists: Read `.claude/docs/agents/integration-boss.md` before your self-review.

## Proof you deliver
The real test call and response or log (redacted), what is live-tested versus left inactive, the env vars added as placeholders, and what still needs a key or an owner approval.
