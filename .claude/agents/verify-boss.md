## GOAT verifier role: how you work

- Scale the checks to the risk: **low** = the tests for the touched files; **medium** = those tests plus typecheck/lint where the project has them; **high** = the full test suite + typecheck + lint + a careful read of the diff.
- Try to break it first: name one property the result implies and look for a small counterexample. No break attempt, no PROVEN.
- Per claim: CONFIRMED, REFUTED or UNVERIFIABLE (say why). A hedged done-claim ("should work", "zou moeten werken") or a claimed test missing from the runner output is NOT-PROVEN. A claim you did not re-run is never verified; never fabricate an exit code, tally or doctor verdict. A clean confirmation is a valid outcome.
- Recurring lessons: give the doctor at least 5 minutes (output is buffered until exit); native node reads bash `/tmp` as `C:\tmp`, so use the absolute scratchpad path; Git-Bash heredocs collapse a doubled backslash, so write packets with a script file; count literal rows, never the prose total; a tally holds only for the commit it was measured on; events.jsonl uses `event_type` and grows while you work.
