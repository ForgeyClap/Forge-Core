**MODEL ROUTING (quota tiering).** Config `model-tiering` (default on) switches this on; off = every subagent runs on the session's own model. It follows the **GOAT router** (owner HARD rule 2026-10-06; routes in `.claude/FORGE_MODEL_ROUTING.json`, read it). The Lead is the router on `sonnet` / effort medium (recommend `/model sonnet` once when the session runs elsewhere — advice only; never set `CLAUDE_CODE_SUBAGENT_MODEL` or `CLAUDE_CODE_EFFORT_LEVEL`). (1) **Triage** — Head Chef (sonnet/low) gives every work package `{route, risk, checks}`: `quick` (small, 1–2 files → sonnet/low) · `build` (normal feature or fix → opus/medium) · `deep` (architecture, migrations, auth, payments, data, production, security, or unclear → opus/xhigh). (2) **Dispatch** the owning Boss — ultracode is on by default (`"ultracode": true` in `~/.claude/settings.json`), so the preferred form is a fresh Workflow per substantive task (no fixed templates) with `agent({agentType:'<boss>', label:'<Boss Name> · <part>', model:<route model>, effort:<route effort>})`, one fresh-context agent per part. The Boss frontmatter model + effort apply inside a Workflow and opts override them, so pass `model` + `effort` when the route differs from the Boss default; an `agent()` without a routed `agentType` or opts inherits the session model and is denied by `~/.claude/hooks/goat-workflow-guard.cjs`. Fallback when ultracode/workflows are off: `Agent({subagent_type:'<boss>', model:<route model>})`, effort = the Boss frontmatter default (the Agent tool has no effort param). Trivial asks stay solo; ultracode drops the built-in cost guards, so triage + low/medium routes and the usage-guard stay the cost control (`.claude/FORGE_MODEL_ROUTING.json` → `ultracodeDispatch`). (3) **Verify** — Verify Boss (sonnet/medium) after EVERY package: checks scaled to risk, PASS/FAIL with evidence, never edits. (4) **Escalate ONCE** on FAIL: process failure (skipped a file, tests not run) → more effort first; capability failure → bigger model (build → deep → escalate `fable`/high). A second FAIL stops and is reported honestly. Fable is never chosen up front; `haiku` is no default route; pure mechanical edits use `Edit` with no subagent. (5) After an escalation, one line `<YYYY-MM-DD> <task pattern> → <route that worked>` in `.claude/agent-memory/head-chef/MEMORY.md`. Log the ACTUAL model used (`agent_model_used`). The global Stop hook test gate (`.claude/goat-gate.json`) blocks a stop while related tests fail. Forge cannot auto-switch the session model — only recommend.

**CACHE DISCIPLINE (usage-minimisation research 2026-09-26 — every request re-sends the cached context, and a cache miss costs roughly 25-40x a cache read of the same content).** Pick the session model and effort ONCE at the start and keep them for the whole session — a mid-session `/model` switch, or a skill/command whose frontmatter names a different model, forces the next request to re-read the full conversation with no cache hit. Don't add or remove MCP servers or tools mid-session either, for the same reason. Run one task per session rather than keeping one session open all day for unrelated work — start fresh or resume from a summary instead. Use `/compact` at a natural break between tasks while the cache is still warm (not right after a long idle gap, which already missed the cache); use `/rewind` instead of `/compact` to abandon a path, since it truncates back to an already-cached prefix rather than building a new one. Route a genuinely cheaper model through a subagent hand-off, never a same-session model switch. None of this changes model choice for security/review-critical/high-risk work — MODEL ROUTING above routes those to the deep route (opus/xhigh) up front.

**PERMANENT BOSSES + QA LOOP + NVIDIA ROUTING.** Teams use the 12 FIXED Bosses (`.claude/config/agents/agent-registry.json` — Boss, Head Chef, Review/Test/UI/SEO/Security/Skill/Search/Build/Integration/Docs Boss); never ad-hoc names; small task = fewer Bosses, same names. Skills auto-attach (core map + project-type bundle). Enforce the fix-loop: subagent self-review → Test Boss → domain Bosses → Review Boss; fail → failure report → Boss → Head Chef → fix → re-test (bounded). For in-task LLM work call NVIDIA via `.claude/forge-bin/nvidia-provider.cjs` per `.claude/config/models/model-capability-matrix.json` (fit first; a mock is never presented as real; key only from `.env`/`~/.claude/nvidia.env`, always masked). See forge-core "PERMANENT BOSSES + QA FIX-LOOP + NVIDIA-FIRST MODEL ROUTING" + `.claude/docs/model-routing.md`.
