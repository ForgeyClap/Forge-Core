## 7. Subagent Outputs / Artifacts
Each subagent produces something real: log `subagent_artifact_created` (≈ `agent_artifact_created`: artifact + path + kind), `agent_handoff`, `subagent_completed`/`subagent_failed` (carry the work package's `wp_id` on both — that is what closes its armed manifest entry). **For every work package logged in step 5, also log `wp_completed` carrying that exact `wp_id` (`{"wp_id":"<id>"}`) the moment it really finishes — or `wp_failed` with the same `wp_id` when it does not.** This is what lets the run contract (step 14) match an armed work package to its real outcome; log it whether or not the manifest was armed for this run. Didn't run → `NOT USED`; thinking-only role → `INTERNAL ROLE ONLY` (status `internal`). No decorative agents/artifacts.

## 8. Lead Review + Rework Loop (bounded)
The Lead Agent **reviews all subagent outputs**: log `lead_review_started` → `lead_review_completed`. For anything incomplete/weak/broken/improvable, log `rework_task_created` (`target`, `issue`, `severity`, `reason`, `required_fix`, `retest_requirement`) → `rework_assigned` → the right subagent fixes (`rework_started`/`fix_started` → `rework_completed`/`fix_completed` with `files_changed`) → `retest_started` → `retest_completed`. **Critical/high must be fixed before final output; medium/minor may be fixed or reported. Max 2 loops default / 3 high-end. Never loop forever**; if blocked, report honestly and ask the user.

## 9. Merge & Synthesis
Collect the reviewed/reworked outputs, resolve conflicts, create the merged result. Log `merge_started` → `merge_completed` + a merged `agent_artifact_created`.

## 10. Codex Review + Unlock (optional, strong for code/architecture/automation/dashboard/refactor/high-end)
**Config `codex-review` decides whether this runs:** `auto` (default) = on important code (auth, payments, data, migrations, large refactors, automation) when the Codex CLI is installed and logged in on this machine — not installed or not logged in → report `NOT AVAILABLE` in one line and continue; `on-request` = only when the owner asks; `off` = skip and report `Codex not invoked (config off)`. When it runs: run `codex-reviewer` (`/codex:review`). Log `codex_review_started` → `codex_finding` per issue → `codex_review_completed`. **If Codex truly runs** → CODEX REAL INVOKED; **if it can't** → run the **Codex unlock diagnosis** yourself (`codex_diagnosis_started`→`_completed`): actually run `codex --version`, check auth, `git status`, TTY/trust gate, and capture stdout/stderr + exit code + orphan check — write the real findings to `artifacts/codex-unlock-diagnosis.md` (log `codex_manual_command_created` only as the diagnosis's internal record of the exact command that was attempted, never as an instruction for the user); in the chat say in one plain line that Codex was not run this time and why — **never construct or hand the beginner a command to type**. Report the exact state — **CODEX REAL INVOKED · BLOCKED: TRUST/TTY · BLOCKED: NO GIT · BLOCKED: NO OUTPUT · NOT AVAILABLE · NOT INVOKED · FALLBACK USED** (events `codex_trust_gate_detected`/`codex_interactive_retry_required`/`codex_retry_started`/`_completed`/`_blocked`). **Never fake Codex or claim proof without real output.** ECC `code-reviewer` may be a labeled fallback.

## 11. Quality Gate → Final Output
Log `quality_gate_passed` when the quality target is met (then `final_output_created`), or `quality_gate_blocked` with a `reason` (`max_iterations_reached` / `unresolved_critical` / `codex_not_invoked`). Report every loop iteration honestly. For a cheap independent second pass, run Claude Code's built-in skills yourself when useful — `/code-review` (diff review in a fresh subagent), `/security-review` (security pass on the pending changes), `/verify` (build-and-run check); nothing to install, and if one is not available in this Claude Code version, say so and use `forge-code-review`.

## 12. Memory Update (always)
After a real finalize, `forge-finalize` also refreshes the readable knowledge vault in `.claude/forge-vault/` by itself (Home, runs, decisions, topics — plain markdown with links, optional Obsidian graph; config `vault`, default on). Update `FORGE_MEMORY.md` · `FORGE_TASK_HISTORY.md` · `FORGE_AGENT_LEDGER.md` (each row has a **Runtime** + status; statuses ONLY: `ECC REAL INVOKED` · `ECC SKILL LOADED` · `NATIVE AGENT INVOKED` · `INTERNAL ROLE ONLY` · `NOT USED` · `FAILED` · `BLOCKED`; note **custom subagents/skills** created) · `FORGE_DECISIONS.md` on meaningful decisions. Update `FORGE_SESSION_STATE.json` (`last_activity`). Log `memory_updated` / `decision_logged`. **Retention = config `cleanup`:** `report` (default) → `node .claude/forge-bin/forge-retention.cjs scan` only (says what could go, deletes nothing); `auto` → `node .claude/forge-bin/forge-retention.cjs apply` (which itself refuses with exit 3 unless config `cleanup` is `auto` — never pass `--force` without an explicit owner request).

## 13. Dashboard Update + Browser Proof
Events are already streamed live (steps above). If asked to start the dashboard, start it as in `dashboard` above, health-check `http://127.0.0.1:4100/api/health` and report `http://127.0.0.1:4100` only when that check passed — never fake a start. The FLOW lens renders the studio layout (preflight band → mission → lead → master plan → subagents → outputs → **Artifact Collector** (large swarms) → lead review/rework → fix/retest → merge → codex → final), with honest runtime/custom/derived badges, clean category labels + Live/Replay. **Browser proof (v7.1):** if Playwright/Chrome-headless is available, open the dashboard → FLOW → fit → capture → write `artifacts/dashboard-browser-proof.md` (`browser_proof_started`→`browser_screenshot_captured`→`browser_layout_verified`). If unavailable, mark **PARTIAL** with the exact reason (`browser_proof_blocked`) — never claim a screenshot you didn't take.

## 14. Final Report  → load skill `forge-report`
**RUN-CONTRACT GATE (required BEFORE `run_completed` — wired 2026-08-02; before this date the gate existed but had no call site and was evaluated exactly 0 times in 846 real events, which the owner experienced as "agents forget the tasks").** One recipe: run `node .claude/forge-bin/forge-runcontract.cjs plan --run <run_id>` and follow its sequence (gate evidence → final-report.md → green check → `run_completed` → `check --finalize`). A red step is unfinished work (or an `owner_override` with a real reason) — **never log `run_completed` over a red contract.** A failed run closes with `run_completed` carrying `"status":"failed"`.
Write `.claude/forge-runs/<run_id>/final-report.md` as step 2 (log `report_generated`; set run.json `status`→`completed`/`failed` + `finished`). Include: blueprint summary, **Skill Discovery** (skills selected/assigned/created/missing), prompt improvements, agents used (incl. **custom subagents** + why) + what each did, artifacts, files read/changed, evidence, **ECC status block**, **Codex status** (the exact v7.1 state + diagnosis/manual-command if blocked), **Browser proof status** (screenshots captured or exact reason unavailable), rework loop (tasks created/fixed), **CLAUDE.md created/updated/no-change/conflict + what was preserved**, **custom SKILL.md files created/updated/used + Skill Registry status**, fresh-install verification (if run), checks run, memory update, dashboard update, session mode, what was **not** done, **strict verdict** (FULL PASS / PASS CORE·PARTIAL PROOF / PARTIAL / BLOCKED / FAIL + per-layer: Core·Codex·Browser·Dashboard·Isolation·Overall), next step. Reflect only checks actually run — **no fake claims**. **For beginners, also:** a plain-language **"Wat is er veranderd"** summary (3–6 short sentences, no jargon: what works now, what changed, what was not done); on a Pro plan (known from `/setup-forge` or the owner — never guessed) one line of model advice (`/model sonnet` — the GOAT router; advice only, Forge cannot switch the model); and end every completed run with one line in the owner's language (config `language`): `Volgende taak ongerelateerd? Typ eerst /clear.` (nl) or `Next task unrelated? Type /clear first.` (en)

## Quality Loop (steps 8–11, autonomous)
Lead review → assign rework → subagents fix → retest → merge → (codex) → check quality target. Repeat until: quality target met · max iterations (2 / 3 high-end) · blocked by missing info · user approval required. Each iteration logs its own events and ends with a gate verdict, reported honestly.

## Honesty (hard rule)
`previewing` = work package logged but not executed yet · `INTERNAL ROLE ONLY` = conceptual/thinking role · `derived from event log` = synthetic/un-`agent`-tagged · `Codex not invoked` stated, never synthesized. **No fake agents, custom subagents, custom skills, Codex, tests, files changed, live activity, or progress.** A custom subagent/skill must have a real reason + work package + a real output (or honest BLOCKED). **ECC honesty:** never present a native role as ECC; if ECC was attempted but unavailable/blocked/failed, say so and label the fallback `runtime:"native"`; if ECC genuinely wasn't needed, say that. **Session Mode** grants no extra permission — project isolation/ECC-first/approval gates always apply.

## Tool hooks for steps 7 and 12 (WP-16, 2026-10-10 — additions outside the verbatim block)
- **Step 7, L3/L4 runs only:** for each real deliverable, store its record with `node .claude/forge-bin/forge-artifact.cjs store <artifact_id> '<json with path, kind, wp_id>' --run <run_id>` — it writes the secret-redacted `.claude/forge-artifacts/<artifact_id>.json` and logs `artifact_stored` (the artifact stage `forge-trace.cjs` reads). Only for a file that really exists; skip on L1/L2.
- **Step 12, L3/L4 runs only, after `forge-distill.cjs --run <run_id>`:** run `node .claude/forge-bin/forge-reinforce.cjs --store .claude/agent-memory/global/lessons.jsonl --runs .claude/forge-runs` — it updates lesson utility in that store only, from real run outcomes (`forge-verify`); report its `reinforcedGood`/`reinforcedBad` counts, or that it was not run. Add `--dry-run` when the owner only wants to see the effect.
