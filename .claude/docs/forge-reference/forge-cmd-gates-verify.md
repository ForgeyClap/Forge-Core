**GATE HOOK — the yes-path (config `gate-hook`, default on).** A PreToolUse hook (`.claude/forge-bin/forge-gate-hook.cjs`) really stops five kinds of command before they run: destructive deletes, killing processes by name, git commands that throw away uncommitted work, commands that hide what they would run (`eval`, `Invoke-Expression`, `sh -c` on a variable, a pipe straight into a shell), and commands that print a secret file (`.env`, keys, credential files; the safe variant shows only the variable NAMES: `node .claude/forge-bin/forge-env-names.cjs .env`). When it blocks a command (exit 2), Forge (1) says in one plain sentence exactly what would have been deleted, killed, discarded or shown, and offers the safe variant first (move to a dated backup folder instead of deleting, stop the one process by its exact PID, commit or stash before discarding); (2) only when the owner explicitly answers yes to THAT command, runs `node .claude/forge-bin/forge-config.cjs set gate-hook off --once "<the owner's words>"` itself, runs the approved command once, then runs `node .claude/forge-bin/forge-config.cjs set gate-hook on` and checks in the same turn that `node .claude/forge-bin/forge-config.cjs get gate-hook` shows `on` again — telling the owner that the one-off also switches itself back on after 10 minutes; (3) never switches the hook off without `--once`, never reuses one yes for a second command, and never asks the owner to run the command themselves; (4) logs `owner_override` with the owner's exact words (`{"gate":"<gate id>","quote":"<the owner's words>","command":"<what ran>"}`).

**VERIFY-AND-CORRECT + SCREENSHOT PROOF (per task).** After each meaningful task: prove the claim is real (file exists / test actually passed / agent actually ran / module renders) before logging done or telling the user it works. Where visual, screenshot-loop the app view, the Forge dashboard FLOW, and (when Paperclip is used) the Paperclip agent tabs to confirm reality (agents have real instructions+skills+runs, no open "complete" gaps). Mismatch → fix if clearly fixable in scope, else surface as a blocker. See forge-core "PER-TASK VERIFY-AND-CORRECT + SCREENSHOT-LOOP PROOF".
