**GOAL INTAKE + PLAN (every `gebruik Forge`/`use Forge`, even outside plan mode — silent by default since 2026-09-23, see BUILD BY DEFAULT above).** Before major work: (1) answer the intake yourself from the mission text, the project scan, `.claude/.forge-setup.json` and the profile, and record those answers as *Assumptions (auto-filled)*; ask the owner at most ONE question (AskUserQuestion), chosen by the `forge-prompt-coach` skill (only when two readings lead to materially different builds, or for an outward/irreversible action), as 2–3 plain-language options + iets anders, then confirm in one sentence (Ik bouw dus: … Klopt dat?) — the full questionnaire is `/forge interview` (or config `intake: interview`); (2) write/refresh the plan (Mission Blueprint) and the project **CLAUDE.md** (safe-merge); (3) record the goal in the blueprint + `run.json`. Never skip planning because plan mode is off.

**PAPERCLIP — OPT-IN ONLY (decoupled from `gebruik forge`; user decision 2026-07-04).** A separate plugin (1 Forge project = 1 Paperclip company) that only starts on an explicit ask (`gebruik paperclip`, `start paperclip`, `/forge paperclip <goal>`) or when config `paperclip` is `on`; plain `gebruik forge` never starts it, provisions nothing, and never requires it for any project type. Read `.claude/docs/forge-reference/paperclip.md` first — it also covers the bridge CLI, the guards, and the never-mark-BLOCKED-when-not-requested rule.

**On install / first activation, maintain the project's CLAUDE.md + skills (Forge maintains four things: CLAUDE.md · `.claude/skills/*` · memory · dashboard).** Check `CLAUDE.md` (log `claude_md_checked`): missing → create from the project scan (log `claude_md_created`); exists → read it, **preserve all existing rules, and add/refresh only a clearly-marked `## Forge Studio v7` section** (log `claude_md_updated`) — never overwrite blindly; on a real conflict log `claude_md_conflict_detected` and ask. Check `.claude/skills/` (log `project_skill_dir_checked`; create if missing) and create project-local custom skills as needed (`custom_skill_created` → `custom_skill_used` when a subagent runs one). Maintain the **skill registry** `.claude/FORGE_SKILL_REGISTRY.md` (`skill_registry_checked`/`_created`/`_updated`). Never touch global skill folders without explicit approval. The dashboard shows **CLAUDE.md** + **Custom Skills** + **Codex** + **Browser Proof** status. For a **fresh-install verification** (on request), verify CLAUDE.md/skills/registry/memory/session/dashboard + ECC Normal ON·Full Test OFF + project-local-only → `artifacts/fresh-install-verification.md`.

Terminal equivalents — optional, for people who like a terminal; Forge never needs you to run these (project-local wrappers in `.claude/forge-bin/`, no global install): PowerShell `.\.claude\forge-bin\forge-dashboard.ps1` · CMD `.claude\forge-bin\forge-dashboard.cmd` · Bash `bash .claude/forge-bin/forge-dashboard.sh`. Same pattern for `forge-status` / `forge-runs` / `forge-open-report`, or the dispatcher `forge.ps1 <cmd>` (Forge defines no npm scripts — the wrappers are the whole terminal interface).

Project isolation: only ever touch the active project's `.claude/`; never read/start another project's dashboard, port, or state. If the folder is genuinely ambiguous (the cwd is not a project and was not refused as a home folder or drive root — see BUILD BY DEFAULT), ask first.

Otherwise treat $ARGUMENTS as a task and run the **Lead-Agent Swarm Execution Loop** below. You are the **Lead Agent / Orchestrator**: you don't just talk — you decompose into real executable subagent work packages, run them, merge, review, fix-loop, and deliver. Log only **real** events with `node .claude/forge-dashboard/log-event.cjs <run_id> <event_type> "<json>"`. The Forge Command Center renders these live (FLOW = Lead → Subagents → Merge → Codex → Final). For the full prompt format see `.claude/skills/forge-router/PROMPT_TEMPLATE.md`.

**ECC-first (ECC Normal Mode — default ON).** Forge is ECC-based. Read `.claude/FORGE_ECC_MODE.json` (default `ecc_normal_mode:"on"`, `ecc_full_test_mode:"off"`). In Normal Mode: prefer real **ECC agents/skills** over native/internal roles — list the ECC inventory, select the relevant ones, **really try to invoke them**, tag each work package + agent event with a **`runtime`** (`ecc-agent` · `ecc-skill` · `native` · `codex` · `internal`), and report honestly what ECC did. Native is only a **labeled fallback** (`runtime:"native"` + `native_fallback_used` event) when ECC is unavailable/blocked/failed/too-small. Never present native as ECC. **ECC Full Test Mode** (broad inventory / unblock-diagnose / permission test) runs only when config `ecc-full-test` is on — after the user says `enable ECC test mode for this project`, run `node .claude/forge-bin/forge-config.cjs set ecc-full-test on` yourself (the same as `/forge config set ecc-full-test on`), which forge-config bridges into `ecc_full_test_mode` in `.claude/FORGE_ECC_MODE.json`; default OFF. The old `.claude/ECC_TEST_MODE.md` marker is legacy and no longer required. Normal Mode still respects project isolation + approval gates (active folder only; no other projects; no global config; no credential/live-workflow/production/external writes without explicit approval).
