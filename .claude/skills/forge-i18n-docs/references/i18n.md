# forge-i18n-docs — i18n in detail

Forge-native. Read with `SKILL.md`; the hard rules there win.

## Catalog layout and keys
- One file per locale (and namespace if large): `messages/nl.json`, `messages/en.json`, or
  `locales/<lang>/<namespace>.json`. Mobile: Flutter ARB (`app_nl.arb`), Android `values-nl/strings.xml`,
  iOS String Catalog (`.xcstrings`).
- Keys describe place and purpose, not the text: `checkout.summary.total`, not `total_price_text`. Keep keys
  stable when the wording changes; remove unused keys in the change that removes their last use.
- The source locale is complete. Other locales may lag, but the app falls back to the source text, never to the
  raw key. A CI check lists missing and unused keys per locale.

## ICU MessageFormat
```
{count, plural, =0 {Geen resultaten} one {# resultaat} other {# resultaten}}
{role, select, admin {Beheerder} other {Gebruiker}}
Welkom terug, {name}. Je hebt {count, plural, one {# nieuw bericht} other {# nieuwe berichten}}.
```
- Plural categories differ per language (CLDR): Dutch and English use `one` and `other`; Polish, Russian and
  Arabic need more. Never assume two forms in code.
- Keep the whole sentence in one message so translators can reorder words. For rich text use tags inside the
  message (`<link>voorwaarden</link>`) rendered by the library, not HTML strings.

## Formatting with Intl
- `Intl.DateTimeFormat(locale, { dateStyle: 'medium', timeZone })`, `Intl.NumberFormat(locale,
  { style: 'currency', currency: 'EUR' })`, `Intl.RelativeTimeFormat`, `Intl.ListFormat`, `Intl.PluralRules`.
- The currency comes from the data (the order's currency), not from the UI locale. `nl-NL` renders
  `€ 1.234,56`; `en-IE` renders `€1,234.56`.
- Parse user input per locale too (decimal comma in Dutch), or use input types that do it.
- Sort and compare text with `Intl.Collator(locale)`.

## Routing and detection (web)
- Locale in the path (`/nl/...`, `/en/...`) with one default. The root redirects by stored preference, then by
  `Accept-Language`, and the user can always switch. Never lock a language by IP.
- Translate slugs only when the content owner wants it; keep a mapping so the language switcher lands on the
  same page. Set `<html lang>` per page; hand the alternates to `forge-web-quality`.

## RTL
- `dir="rtl"` on `<html>` for Arabic, Hebrew, Persian and Urdu. Use CSS logical properties and values
  (`padding-inline`, `inset-inline-start`, `text-align: start`). Mirror directional icons such as arrows, not logos
  or media controls. Check with a real RTL locale screenshot.

## Pseudo-locale and tests
- A pseudo-locale (accented characters, about 40% padding, brackets around each string) exposes hard-coded
  strings and clipping. Run the main screens with it before release.
- Unit tests: each locale file parses, has no missing keys against the source, and every ICU message compiles.
- Snapshot dates, numbers and currency for each shipped locale.

## Translation workflow
- Give translators context: a description per key or screenshots. Machine output is marked as a draft (a metadata
  field or a separate file) until reviewed. Record who reviewed which locale and when.
